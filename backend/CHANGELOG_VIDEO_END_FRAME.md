# 视频最后一帧提取与上一镜衔接功能

## 概述

实现了视频生成完成后自动提取最后一帧，并在生成下一镜视频时使用上一镜的最后一帧作为参考图，确保镜头之间的平滑衔接。

## 功能特性

### 1. 视频最后一帧提取
- ✅ 视频生成完成后，使用 FFmpeg 自动提取最后一帧
- ✅ 与视频同目录同名保存为 JPG（自动跟随项目存储布局与章节分目录）
- ✅ 存储**项目内相对路径**到 `video_version.end_frame_path` 字段（与 `file_path` 约定一致）
- ✅ 提取失败不影响视频生成成功（仅记录警告日志）

### 2. 上一镜衔接
- ✅ 生成视频时自动查询上一镜的视频最后一帧
- ✅ **仅同场景时引用**：跨场景引用会把上一个场景的画面直接喂给模型
- ✅ **当前关键帧固定 @Image1**，上一镜末帧为 @Image2，其余参考图依次顺延
  （单图 Provider 只取首图，首图必须是本镜起始画面）
- ✅ 入队时校验末帧文件可读，失效则本次不引用
- ✅ 提示词模板中【上一镜结束状态】段落引用该图片

### 3. 新的视频提示词模板结构

**旧模板**（5个段落）：
```
【全局风格】
【参考】
【执行】
【镜头与声音】
【禁止项】
```

**新模板**（10个段落）：
```
【全局风格】
【角色锁定】        ← 从【参考】中分离，专注角色一致性
【物品锁定】        ← 新增，独立处理道具参考
【场景锁定】        ← 从【参考】中分离，专注场景元素
【上一镜结束状态】  ← 新增，支持上一镜衔接
【本镜唯一开始状态】← 当前关键帧 + 站位 + 表情
【核心动作】        ← 对应旧【执行】
【镜头】            ← 从【镜头与声音】分离
【声音】            ← 从【镜头与声音】分离，支持画外音
【禁止项】
```

**关键改进**：
- 更清晰的段落职责划分
- 智能 anchors 分配（根据关键词自动将图片引用分配到对应段落）
- 支持 positions（站位）、expressions（表情）、voice_over（画外音）
- 时间轴智能处理（短视频单段式，长视频三段式，自动补充稳定段）

## 技术实现

### 1. FFmpeg 提取命令
```bash
ffmpeg -sseof -1 -i video.mp4 -update 1 -q:v 1 -vframes 1 -y output.jpg
```
- `-sseof -1`: 从视频末尾倒数
- `-q:v 1`: 高质量输出
- `-vframes 1`: 只提取一帧

### 2. 代码变更

#### media_service.py
- `_extract_last_frame()`: 新增方法，使用 FFmpeg 提取最后一帧
- `handle_video()`: 视频完成后提取最后一帧并更新数据库
- `queue_video()`: 查询上一镜结束帧，调整 reference_anchors
- `handle_video()` 参考图准备: 将上一镜结束帧添加到输入图片列表

#### shot_service.py
- `compile_shot_prompt()`: 查询上一镜结束帧，构建动态 anchors

#### prompt_service.py
- `compile_video_prompt()`: 重构模板结构，支持新的段落划分
- 智能 anchors 分配逻辑
- 时间轴智能处理

## 使用示例

### API 流程
1. 生成第一镜视频 → 完成后自动提取最后一帧
2. 生成第二镜视频 → 自动引用第一镜的最后一帧
3. 提示词中自动包含：
   ```
   【上一镜结束状态】
   @Image2：上一镜结束帧，仅用于衔接连贯，不是本镜起始画面。
   （上一镜结束状态描述）
   
   【本镜唯一开始状态】
   @Image1：当前分镜关键帧，锁定构图、人物左右关系和起始站位。
   从（当前开始状态）开始。
   ```

### 提示词示例对比

**有上一镜结束帧时（同场景）**：
```
@Image1：当前分镜关键帧      ← 固定首位，本镜起始画面
@Image2：上一镜结束帧        ← 仅用于衔接，不是起始画面
@Image3：场景布局
@Image4：主角身份
```

**无上一镜结束帧 / 跨场景时**：
```
@Image1：当前分镜关键帧
@Image2：场景布局
@Image3：主角身份
```

图片下发顺序与上述编号严格一致；执行期若末帧文件缺失，直接失败而非静默降级，
避免后续 @Image 编号整体错位。

## 向后兼容性

- ✅ 旧视频记录的 `end_frame_path` 为 NULL，不影响新视频生成
- ✅ 查询时检查 `end_frame_path IS NOT NULL`，并在入队时校验文件可读
- ✅ 0009 迁移清空了历史写入的 URL 值（该格式消费侧无法解析，功能此前从未生效）
- ✅ 如果上一镜没有结束帧，自动降级为原有逻辑

## 性能影响

- FFmpeg 提取最后一帧：~100-500ms（取决于视频大小）
- 数据库查询：增加 1 次 JOIN 查询（已优化索引）
- 存储空间：每个视频额外存储 1 张 JPG（约 50-200KB）

## 未来优化建议

1. **批量提取**：在批量生成视频时，可以并行提取多个视频的最后一帧
2. **缓存优化**：频繁访问的结束帧可以考虑 CDN 缓存
3. **预览功能**：在前端界面展示上一镜结束帧预览
4. **手动调整**：允许用户手动上传或选择特定帧作为衔接帧
