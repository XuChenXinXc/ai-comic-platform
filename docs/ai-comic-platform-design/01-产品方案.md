# AI 漫剧网页平台 V1 方案（分步骤确认版）

## 一、产品定位

开发一个仅供本地自用的 AI 漫剧网页平台。

平台不需要制作成桌面客户端，也不需要公开部署成在线 SaaS。用户通过浏览器访问本地运行的网页，例如 `http://localhost:3000`。

平台由两部分组成：

- **网页前端**：负责项目操作、内容编辑、预览和确认。
- **本地后端**：负责保存项目、调用外部 AI API、下载素材、执行视频合成。

整个制作过程不采用一键串联模式。每个制作步骤相互独立，用户完成当前步骤、检查结果并点击"确认"后，才能进入下一步。

## 二、平台核心工作方式

- 每一个步骤都由用户手动启动。
- 当前步骤完成后不会自动执行下一步。
- 每一步的结果都可以编辑、删除和重新生成。
- 用户确认后，当前版本被锁定并传递给下一步。
- 修改前面的内容时，系统提示哪些后续内容可能失效。
- 每个素材保留生成版本，避免重新生成后覆盖原结果。
- 每个分镜、角色、场景和物品都可以单独重新生成。
- 支持批量生成，但批量生成也必须由用户主动点击。
- 最终合成只使用用户已经确认的版本。
- API 调用失败时，只重试当前任务，不影响其他已经完成的内容。

## 三、推荐的完整制作流程

1. 创建项目
2. 小说分析
3. 剧本改编
4. 角色、场景、物品提取
5. 角色、场景、物品生成
6. 分镜提取
7. 分镜关键帧生成
8. 分镜视频生成
9. 配音与字幕
10. 自动合成与导出

其中第七步"分镜关键帧生成"是建议新增的关键步骤。

## 四、各步骤详细设计

### 第一步：创建项目

用户创建一个新的漫剧项目。

**用户填写内容**

- 项目名称
- 小说正文
- 小说章节信息（可选）
- 漫剧画面风格
- 输出比例
- 输出分辨率
- 目标单集时长
- 使用的 AI 接口配置

**小说输入方式**

第一版支持：直接粘贴小说正文、上传 TXT 文件、上传 Markdown 文件、上传 DOCX 文件。

**项目默认设置**

| 项 | 默认值 |
|---|---|
| 画面比例 | 16:9 |
| 输出分辨率 | 1920×1080 |
| 输出格式 | MP4 |
| 主要语言 | 中文 |
| 字幕语言 | 简体中文 |
| 单集目标时长 | 用户可设置 |
| 漫剧风格 | 用户选择预设或填写描述 |

**用户操作**

保存小说、修改小说、点击"进入小说分析"。在小说分析完成之前，用户仍然可以修改原始小说。

### 第二步：小说分析

用户点击"开始分析"后，平台调用文本模型分析小说。

**分析内容**

故事类型、故事背景、世界观、故事发生时间、故事发生地点、主要人物、次要人物、人物关系、核心冲突、剧情发展、情绪变化、高潮节点、重要伏笔、小说章节结构、适合拆分的剧集节点、不容易直接画面化的心理描写、可能需要旁白的内容。

**页面展示**

分析结果按模块显示：故事概述、世界观、人物关系、剧情时间线、章节摘要、剧集拆分建议、制作风险提示。

**用户操作**

修改分析结果、删除错误信息、补充遗漏内容、重新分析、确认小说分析。

确认后，小说分析结果作为剧本改编的主要依据。

### 第三步：剧本改编

用户确认小说分析后，手动点击"开始剧本改编"。平台将小说转换为适合漫剧制作的剧本。

**剧本结构**

```
剧集
  └── 场次
       ├── 场景信息
       ├── 出场人物
       ├── 剧情内容
       ├── 人物动作
       ├── 人物对白
       ├── 旁白
       ├── 情绪
       └── 转场方式
```

**剧本改编内容**

- 自动拆分剧集
- 自动拆分场次
- 将小说叙述转换为画面动作
- 将心理描写转换为动作、表情或旁白
- 生成角色对白
- 生成旁白
- 删除不适合视频化的重复描述
- 保留关键剧情和人物关系
- 控制每集整体节奏
- 估算每集时长

**用户操作**

用户可以逐集、逐场修改：场次顺序、场景内容、人物对白、旁白内容、人物动作、情绪、剧集拆分位置、预计时长。

平台提供：重新生成整集、重新生成单场、扩写场次、缩短场次、修改对白风格、修改叙事节奏。

用户确认剧本后，进入素材提取。

### 第四步：角色、场景和物品提取

这一阶段应当从"用户确认后的剧本"中提取，而不是只从原小说中提取。

原因是最终制作使用的是改编剧本，剧本中可能已经：合并了人物、删除了人物、调整了场景、增加了服装、增加了关键物品、改变了时代或地点描述。

**角色提取**

每个角色包含：角色姓名、角色别名、性别、年龄、身份、性格、外貌、发型、发色、身材、默认服装、服装变体、表演特点、与其他角色的关系、出现在哪些剧集和场次、是否需要固定配音。

**场景提取**

每个场景包含：场景名称、场景类型、室内或室外、时间、天气、建筑风格、空间布局、光线、色彩氛围、主要陈设、出现在哪些剧集和场次。

同一地点的不同时间状态，应当作为场景变体保存，例如：

```
林家客厅｜白天
林家客厅｜夜晚
林家客厅｜停电状态
```

**物品提取**

只提取对画面或剧情有实际作用的物品，例如：武器、信件、戒指、手机、车辆、法器、特殊服饰、剧情线索、角色经常携带的标志性物品。

普通桌椅、杯子等不需要全部建立独立素材。

**用户操作**

新增角色、场景或物品；合并重复项目；删除无关项目；修改描述；设置重要程度；设置是否需要生成参考图；确认提取结果。

### 第五步：角色、场景和物品生成

用户确认素材列表后，手动进入素材生成页面。这一阶段用于建立后续分镜必须使用的统一参考素材库。

#### 5.1 角色生成

每个主要角色建议生成：正面头像、侧面头像、半身图、全身图、正面标准表情、主要服装、服装变体、可选表情参考图。

用户可以：修改角色提示词、上传自己的参考图、生成多个候选版本、选择一个主版本、锁定角色形象、给角色绑定配音声音。

角色锁定后，后续分镜必须使用该角色的参考图。

#### 5.2 场景生成

每个主要场景建议生成：标准全景图、不同视角参考图、白天或夜晚变体、必要的天气变体、场景色彩和光线参考。

场景参考图不一定直接用于最终视频，但应当作为后续分镜生成的视觉依据。

#### 5.3 物品生成

重要物品建议生成：标准外观图、正面图、侧面图、使用状态图（可选）。

如果物品已经包含在角色参考图中，例如角色固定佩剑，可以将其与角色服装绑定，不需要单独重复生成。

#### 用户确认

每一个角色、场景和物品都必须有以下状态：

```
未生成 → 生成中 → 待确认 → 已确认 → 已锁定
```

重要素材未确认时，不允许进入分镜生成。

### 第六步：分镜提取

用户确认角色、场景和物品后，点击"生成分镜"。平台根据剧本自动拆分镜头。

**每个分镜包含**

分镜编号、所属剧集、所属场次、镜头类型、景别、摄像机角度、摄像机运动、场景、出场角色、当前服装、使用物品、人物位置、人物动作、人物表情、当前说话人、对白、旁白、口型幅度、预计时长、画面描述、图像提示词、视频提示词、负向提示词。

**分镜拆分原则**

一个镜头不应包含过多动作。例如下面的内容不适合放在一个分镜中：

```
角色站起来，走到门口，打开门，看见敌人后震惊地后退。
```

应拆分为多个镜头：

```
镜头1：角色站起身。
镜头2：角色走向门口。
镜头3：角色打开门。
镜头4：门外出现敌人。
镜头5：角色震惊后退。
```

这样可以提高视频生成成功率。

**用户操作**

修改分镜描述、拆分分镜、合并分镜、调整分镜顺序、修改景别、修改运镜、修改对白和旁白、修改预计时长、重新生成单个分镜、重新生成整场分镜。

用户确认分镜后，进入分镜画面生成。

### 第七步：分镜关键帧生成

这一环节建议单独增加，不能直接从文字分镜跳到视频生成。

**增加这一环节的原因**

直接使用文字生成视频容易出现：角色长相变化、角色服装变化、场景变化、人物数量错误、物品丢失、构图不可控、首帧与预期不一致。

生成视频后才发现基础画面错误，浪费视频接口费用。因此建议先为每个分镜生成一张关键帧。

**关键帧生成使用内容**

项目统一画风、角色参考图、场景参考图、物品参考图、分镜画面描述、景别、人物动作、人物表情、光线、构图、负向提示词。

**用户操作**

单独生成一个分镜、批量生成当前场次、批量生成当前剧集、查看多个候选版本、修改提示词、重新生成、上传自己的图片替换、选择当前使用版本、锁定关键帧。

只有确认过关键帧的分镜，才可以进入视频生成。

### 第八步：分镜视频生成

用户确认关键帧后，进入分镜视频生成。默认采用：

```
确认后的分镜关键帧
+ 分镜视频提示词
+ 动作描述
+ 运镜描述
+ 预计时长
```

调用图生视频 API。

**每个分镜支持**

单独生成、批量生成、暂停生成、重新生成、保存多个视频版本、选择当前版本、修改动作幅度、修改镜头运动、修改视频时长、下载单个分镜视频、上传本地视频替换。

**视频生成状态**

```
未生成 / 等待中 / 生成中 / 下载中 / 待确认 / 已确认 / 失败
```

用户必须逐个或批量确认视频。平台不能因为某个分镜失败，就重新生成全部视频。

### 第九步：配音与字幕

配音和字幕放在同一个功能页面中。这个设计是合理的，因为两者都依赖同一份对白文本。

但在系统内部，必须按照固定顺序执行：

```
生成配音
→ 获取配音时长和时间戳
→ 校验配音时长是否超出分镜视频时长
→ 超出则回到配音环节调整，直到不超出
→ 生成字幕时间轴
```

不能同时无顺序执行。

**关于口型同步：** V1 不做口型同步后处理。现成的口型模型（Wav2Lip / SadTalker / LatentSync 及商业 API）
都基于真人脸训练，对漫剧画风的脸会检测失败或产出嘴部畸变；而且它会重新编码第八步刚确认过的视频，
使交付版本不是用户确认过的那一版。口型改为**脚本级标注**（对白字数决定微/中/大嘴部幅度），
写进视频提示词交给视频模型处理，这也是 `dongtai-man-writing` 里口型分级的原本用途。

**硬性约束：配音时长不允许超过分镜视频时长。**

第八步确认的分镜视频时长是基准，配音必须适配视频，不允许反向拉长或重新生成视频。校验以分镜为单位，比较该分镜全部对白与旁白音频的总时长（含停顿）与视频实际时长。

超出时平台标记该分镜为"配音超长"，并显示超出的秒数，用户可采取以下处理方式：

- 提高语速后重新生成配音
- 精简对白或旁白文字
- 缩短句间停顿
- 拆分对白到相邻分镜
- 手动上传符合时长的音频

平台不自动裁剪音频，也不自动变速，避免出现丢字或音调失真。"配音超长"的分镜不允许确认，也不允许进入合成。

#### 9.1 角色声音设置

进入该步骤前，每个有对白的角色需要绑定：配音服务商、声音 ID、声音克隆 ID（可选）、默认情绪、默认语速、默认音调、默认音量。

旁白需要绑定独立的旁白声音。

#### 9.2 分镜自动配音

每个有对白或旁白的分镜，平台自动生成：角色对白音频、旁白音频、音频实际时长、字词级或句子级时间戳、当前配音版本。

生成后平台立即计算该分镜的音频总时长与视频时长的差值，并显示时长占用情况，例如：

```
分镜 03-12   视频 5.0s   配音 4.2s   剩余 0.8s   正常
分镜 03-13   视频 3.0s   配音 3.6s   超出 0.6s   配音超长
```

用户可以修改：对白、情绪、语速、音调、停顿、发音、多音字、当前声音。

用户可以只重新生成某一句对白。

#### 9.3 自动字幕

字幕直接使用剧本中的对白和旁白内容。不建议先生成配音，再通过语音识别重新识别文字，因为这样容易出现文字错误。

字幕时间轴优先使用：

1. 配音 API 返回的字词级时间戳
2. 配音 API 返回的句子级时间戳
3. 音频强制对齐
4. 语音识别时间戳

平台自动处理：字幕换行、字幕标点、每行字数、字幕显示时长、多角色连续对白、字幕与镜头时间匹配。

字幕以独立 SRT 文件交付，不烧录进画面，因此不涉及字幕样式与安全区域。

#### 9.4 口型（脚本标注，不做后期同步）

V1 不实现口型同步后期处理。原因：现有口型模型（Wav2Lip、SadTalker、LatentSync 及商业 API）都基于真人脸训练，漫剧风格脸部检测失败或产生嘴部畸变，效果反而比不做更差。

替代做法：口型作为**脚本级标注**保留，按对白长度分三级（微／中／大），写进视频提示词交给视频模型处理嘴部运动。这与 `dongtai-man-writing` 的原始设计一致 —— 口型在那里本来就是"画多少嘴部动作"的作画提示，不是自动对齐需求。

**配音页面建议布局**

每个分镜卡片中显示：视频预览、当前说话人、对白文本、配音播放器、字幕预览、配音状态、字幕状态、配音时长是否超限、重新配音、重新生成字幕、确认按钮。

配音和字幕虽然在同一个页面，但必须允许分别重做。

### 第十步：自动合成和导出

用户确认全部分镜视频、配音和字幕后，进入最终合成页面。

**自动合成内容**

按分镜顺序拼接视频、对齐角色对白、对齐旁白、添加背景音乐、调整对白与音乐音量（对白优先，音乐自动降音）、添加转场、添加片头、添加片尾、统一分辨率、统一帧率、统一视频编码、输出最终视频、导出独立 SRT 字幕文件。

**合成前检查**

检查项分为阻断性错误和非阻断性警告两类。

阻断性错误必须修复后才能合成：

- 存在未确认分镜
- 缺少分镜视频
- 有对白的分镜缺少对白音频
- 缺少字幕
- 视频文件无法播放
- 素材文件丢失
- **音频时长超过所属分镜视频时长**
- 分辨率不一致

非阻断性警告允许忽略后继续合成：

- 字幕时间重叠（只影响 SRT 文件，可自动错开）
- 音频时长明显短于分镜视频时长（画面留白）

用户可以选择：修复问题后再合成，或忽略非阻断性警告并继续。阻断性错误不提供"忽略并继续"选项。

**导出设置**

第一版固定支持：画面比例 16:9、分辨率 1920×1080、格式 MP4、视频编码 H.264、音频编码 AAC、单集导出、全部剧集批量导出。

字幕以独立 SRT 文件交付，与成片同目录同名，播放器自动挂载，不烧录进画面。这样后续修改字幕只改文件，不用重新渲染整条视频。

## 五、推荐的网页导航结构

网页左侧使用固定步骤导航：

1. 项目信息
2. 小说分析
3. 剧本改编
4. 素材提取
5. 素材生成
6. 分镜提取
7. 关键帧生成
8. 视频生成
9. 配音与字幕
10. 合成导出

每一步显示状态：未开始、处理中、待确认、已确认、需要修改。

用户可以回到已经完成的步骤查看内容。如果用户修改了前面的步骤，平台必须提示：

> 当前修改可能影响后续的分镜、视频和配音结果。是否继续修改？

不能直接删除后续内容。

## 六、需要增加的通用功能

### 1. 确认和锁定

每一步都需要两个不同操作：

- **保存**：保存当前修改，但仍可继续编辑。
- **确认并锁定**：确认当前版本，并允许进入下一步。

锁定后仍然可以解锁修改，但需要提示后续影响。具体的影响标记规则见本章第 7 节"失效标记与影响传播"。

### 2. 版本管理

以下内容必须保存多个版本：小说分析、剧本、角色描述、角色参考图、场景参考图、物品参考图、分镜、分镜关键帧、分镜视频、配音、字幕、最终合成视频。

用户可以随时切换当前使用版本。

### 3. 单项重新生成

每一个 AI 生成内容都需要支持：单独重新生成、修改参数后重新生成、保留原版本、选择新旧版本、查看错误原因。

### 4. 批量操作

虽然平台不是全自动串联，但单个步骤内部应该支持批量操作，例如：批量生成所有角色、批量生成所有场景、批量生成当前场次关键帧、批量生成当前剧集视频、批量生成全部配音、批量生成全部字幕。

批量任务完成后仍然需要用户确认，不能自动进入下一步。

### 5. 任务中心

所有外部 API 调用都进入统一任务中心。显示：任务名称、所属步骤、所属角色或分镜、服务商、当前状态、提交时间、重试次数、错误信息、重新执行。

### 6. API 配置

由于平台需要调用多个外部服务，应分别配置：文本模型 API、图像生成 API、视频生成 API、中文配音 API、声音克隆 API。

所有接口都需要支持：自定义接口地址、API Key、模型名称、请求参数、超时时间、重试次数、测试连接。

### 7. 失效标记与影响传播

修改已确认的前置步骤时，平台不删除后续内容，而是给受影响的后续内容打上失效标记。

**数据模型要求**

所有可确认的内容对象（小说分析、剧本场次、角色、场景、物品、分镜、关键帧、分镜视频、配音、字幕）都必须预留以下字段：

| 字段 | 说明 |
|------|------|
| `status` | 未开始 / 处理中 / 待确认 / 已确认 / 已锁定 |
| `stale` | 是否已失效（前置内容变更后置为 true） |
| `stale_reason` | 失效原因，例如"角色林昭的参考图已更新" |
| `stale_source` | 触发失效的上游对象 ID |
| `stale_at` | 失效时间 |
| `source_version` | 生成时所依赖的上游版本号 |

`source_version` 是判断失效的依据：上游内容确认新版本后，下游对象记录的 `source_version` 与上游当前版本不一致，即为失效。

**传播规则**

失效沿制作链单向向下传播，不回溯：

```
小说分析 → 剧本 → 素材（角色/场景/物品）→ 分镜 → 关键帧 → 分镜视频 → 配音/字幕 → 合成
```

传播只标记直接依赖对象，再由被标记对象继续向下传播一层，逐层扩散。例如修改角色"林昭"的参考图后：

1. 引用该角色的分镜关键帧标记失效。
2. 由这些关键帧生成的分镜视频标记失效。
3. 该分镜的配音和字幕不受影响（只依赖对白文本和声音配置）。

依赖关系必须精确到对象级，不能整集或整场一次性标记失效，否则改一个角色会导致全集重做。

**用户可见行为**

- 失效内容在列表和卡片上显示醒目的失效角标与失效原因。
- 步骤导航中该步骤状态显示为"需要修改"。
- 失效内容仍然可以查看和播放，旧版本文件不删除。
- 用户可以选择重新生成，或者确认当前版本仍然可用（"忽略本次变更"），忽略后清除失效标记并把 `source_version` 更新为上游当前版本。
- 合成前检查把失效内容列为警告项，用户可以忽略并继续。

## 七、对原流程的优化结论

原始流程整体没有问题，但建议进行以下四项调整。

### 优化一：增加"分镜关键帧生成"

原流程是：

```
分镜提取 → 分镜视频生成
```

建议调整为：

```
分镜提取 → 分镜关键帧生成 → 分镜视频生成
```

这是最重要的优化。它能够明显提高：角色一致性、场景一致性、构图可控性、视频生成成功率、API 成本可控性。

### 优化二：素材提取必须基于最终剧本

角色、场景和物品提取应放在剧本改编之后。当前安排是正确的。

不建议先根据原小说生成全部素材，因为剧本改编后可能发生角色合并、场景删减或剧情调整。

### 优化三：配音和字幕可以放在同一步，但内部必须分阶段

统一放在一个页面没有问题。但是页面内部必须分别显示：配音、字幕。

两部分可以单独生成、单独修改、单独确认。不能因为修改了一句字幕，就重新生成全部配音。

原方案把口型同步也放在这一步。V1 取消口型同步后处理（原因见第九步 9.4），口型降级为脚本级标注，
在第六步分镜提取时随对白一起产出，写进视频提示词，不占用本步骤的执行阶段。

### 优化四：不需要全自动串联，但每一步内部要支持批量

平台不应该自动从小说一直运行到最终视频。但在单个步骤中，用户仍然需要"批量生成"按钮，否则几十个或几百个分镜逐个点击会非常低效。

正确方式是：

```
用户进入当前步骤
→ 点击批量生成
→ 平台完成当前步骤的全部任务
→ 用户检查和修改
→ 用户确认
→ 手动进入下一步
```

## 八、最终推荐版本

最终平台可以定义为：

> 一个本地运行的网页式 AI 漫剧制作平台。用户按照固定制作步骤操作，每一步独立生成、独立修改、独立确认，不自动进入下一步。

最终流程为：

```
创建项目并填写小说
        ↓
小说分析
        ↓
剧本改编
        ↓
角色、场景、物品提取
        ↓
角色、场景、物品生成与锁定
        ↓
分镜提取
        ↓
分镜关键帧生成与确认
        ↓
分镜视频生成与确认
        ↓
配音与字幕
        ↓
自动合成与导出
```

这套流程比全部自动串联更适合自用平台，因为它能够：控制每一步结果、减少错误向后传递、降低视频 API 浪费、提高角色一致性、方便局部重新生成、保证最终作品质量。
