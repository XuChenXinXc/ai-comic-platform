## Grok 视频接口的四个硬约束

这四条直接改了 schema 和校验规则，实现时绕不开（详见 `02-技术设计.md` §2.5）：

| 约束 | 值 | 影响 |
|------|-----|------|
| 时长 | **6–30 秒整数**，JSON 里必须是纯数字（不能带引号） | `planned_duration_sec` 用 INTEGER + `CHECK BETWEEN 6 AND 30` |
| 参考图 | 最多 **7 张**，只收公网 URL | §7.5 定了丢弃优先级；关键帧和说话角色永不丢 |
| 产物 URL | 带 `expires_at`（unix 时间戳），会过期 | 轮询到 `completed` 必须同 job 内下载落盘，不能只存 URL |
| 输出画质 | 720p | 合成时 FFmpeg 上采样到 1080p + 轻微锐化，保持交付规格一致 |

时长下限 6 秒带来一个连带约束：单集镜头数上限 = 目标时长 ÷ 6。
4 分钟一集最多 40 个镜头。「一镜一事」的拆分标准不放松，装不下就拆两集，
不把多个动作塞回一个镜头（那会显著拉高视频生成失败率）。

不阻塞开工 —— `MOCK_MODE=true` 下静态帧循环足够把前九步全部跑通，
六个实施阶段里只有阶段 5 才需要真实调用 Grok。

## 实施顺序

六个阶段，每阶段可独立验证（详见 `02-技术设计.md` §九）：

| 阶段 | 内容 | 完成标志 |
|------|------|---------|
| 1 | SQLite schema + Pydantic 模型 + 签名函数 + Alembic 初始迁移 | 建库、CRUD、签名稳定性、stale 判定的 pytest 全绿 |
| 2 | Job 表 + JobRunner + 恢复逻辑 + `/api/jobs` | 状态机、重启恢复、409 冲突、断点续跑通过 |
| 3 | Provider 抽象 + MOCK_MODE + 步骤 1–3（项目/分析/剧本） | 网页前三步可手工走通 |
| 4 | 步骤 4–6（素材提取/生成/分镜）+ 参考图绑定 | 绑定契约、缺图失败、批量部分失败通过 |
| 5 | 步骤 7–9（关键帧/视频/配音字幕）+ 配音时长约束 | 逐镜确认可用；需要真实视频服务商 |
| 6 | 步骤 10 合成 + QC + Playwright 端到端 | 一条主链路走完十步 |

阶段 1–2 完成后就要能在 `MOCK_MODE=true` 下跑通全链路，不依赖任何外部 API。
这样前端和状态机的开发不会被 API 额度阻塞。

## 开工前值得先知道的五件事

这些是设计里最容易实现错、且错了要返工的地方：

1. **stale 是算出来的，不是存出来的。** 每个产物记录生成时的上游签名，读取时现算
   当前上游签名比对。不写"标记下游 stale"的递归函数 —— 改一处剧本要递归标记该场次
   下所有分镜、关键帧、视频、配音，漏一条就是静默错误，且只在最终合成时暴露。

2. **`shot_signature` 只覆盖语义字段，不含媒体路径或生成结果。** 如果签名里混进生成
   结果，那么生成一张图就会让签名变化，进而让刚生成的图自己失效。

3. **参考图按 `asset_id` 外键绑定，不按名字匹配。** 名字只做显示。按名字精确匹配时，
   名字对不上不会报错，只是静默不挂参考图 —— 属于查不出来的质量损失。

4. **配音时长不得超过所属分镜视频时长**，视频时长是上限，不反向改视频。超时按
   变速压缩（≤1.15 倍）→ 精简对白 → 调语速重生成 三级处理。这条在合成前检查里是
   阻断性错误，不能忽略。

5. **口型不做后期同步**，只作为 `shot.mouth_level`（micro/medium/large，按对白字数
   派生）写进视频提示词。现有口型模型基于真人脸训练，漫剧风格会脸部检测失败或
   嘴部畸变；且后期同步会让第八步刚确认的视频失效。

## 与本机动态漫 skill 的关系

`C:\Users\Jacks\.claude\skills\` 下的 5 个动态漫 skill（`dongtai-man-character` /
`-rhythm` / `-writing` / `dongtaiman` / `seedance-manual`）是本设计的领域规范来源。

skill 里的约束在平台里从"提示词里的文字要求"下沉为**数据库字段 + 校验规则**，
让平台自动挡住违规内容，而不是靠 AI 每次自觉：

- 一致性锚点（不可变特征 / 禁用变化 / 定妆关键词串）→ `asset` 表字段，第五步锁定核心
- 强动态预算 ≤3、平淡期 ≤60s → `episode` 表 + 第三步门禁
- 动态三级（微/中/强）、嘴部幅度分级 → `shot` / `dialogue_line` 字段 + 校验
- 标准分镜块字段、转场枚举 → `shot` 表结构直接对齐
- `@素材` 引用契约、镜头语言枚举 → `shot_reference_binding` 表 + 提示词编译器

平台产物与 skill 产物语义已对齐，缺的只是一层文本格式适配（`shot` 表 ↔
`04_标准分镜.md` 块格式）。要做「skill 手写一集导入平台出片」或「平台拆完分镜
导出给 skill 精修」时才需要补，不做不影响平台自身闭环。
