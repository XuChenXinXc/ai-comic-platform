# AI 漫剧本地平台 V1 — 核心技术设计

> 配套文档：`01-产品方案.md`。
>
> 本文只实现小说、文字分析、素材与提示词、图片生成、分镜、关键帧和视频生成。
> 不包含配音、字幕、视频合成和多用户系统。

## 一、设计目标

### 1.1 核心目标

平台必须稳定完成以下调用链：

```text
小说正文
├── Text Provider → 小说分析
├── Text Provider → 剧本
├── Text Provider → 角色/场景/物品
│   └── Text Provider → 素材图片提示词
│       └── Image Provider → 素材参考图
└── Text Provider → 分镜（来源可选小说或剧本）
    ├── Text Provider → 分镜图像提示词
    ├── Text Provider → 分镜视频提示词
    ├── Image Provider → 分镜关键帧
    └── Video Provider → 分镜视频
```

### 1.2 非目标

V1 不实现：

- TTS、配音、字幕、口型
- FFmpeg 成片合成
- BGM
- 多用户和登录
- 云端部署
- Redis、Celery 和分布式任务
- 复杂审批和工作流引擎
- 所有模型自动兼容

不同接口协议仍然需要对应的 Provider Adapter。

## 二、技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Python 3.11 + FastAPI | 处理 API、任务和文件下载 |
| 数据校验 | Pydantic v2 | 校验文字模型结构化输出和接口参数 |
| 数据库 | SQLite + WAL | 本地单用户足够 |
| 数据访问 | SQLAlchemy 2.0 Core | 明确 SQL，避免复杂 ORM 关系 |
| 迁移 | Alembic | 保证后续字段调整可升级 |
| 前端 | Vite + React + TypeScript | 适合卡片列表、编辑器和任务轮询 |
| 请求缓存 | TanStack Query | 获取、轮询和刷新任务状态 |
| UI | Tailwind CSS + shadcn/ui | 快速完成本地工具界面 |
| 本地文件 | 文件系统 | 保存图片和视频 |
| 后台任务 | 持久化 Job + 本地线程池 | 不引入 Redis/Celery |
| 视频检查 | ffprobe 可选 | 只检查生成视频是否可解码和实际时长 |
| 测试 | pytest + Playwright | 后端和关键页面主链路 |

开发环境：

```text
前端：http://127.0.0.1:3000
后端：http://127.0.0.1:8000
```

正式本地使用时可以将前端构建产物交给 FastAPI 静态托管，只启动后端一个进程。

## 三、总体架构

```text
React 前端
   │
   ▼
FastAPI API
   ├── Project Service
   ├── Text Generation Service
   ├── Asset Service
   ├── Storyboard Service
   ├── Image Generation Service
   ├── Video Generation Service
   ├── Job Runner
   └── Provider Adapters
          ├── Text Provider
          ├── Image Provider
          └── Video Provider

SQLite：结构化数据
文件系统：图片、关键帧、视频
```

### 3.1 核心原则

- 数据库只保存结构化数据和相对文件路径。
- 图片和视频结果必须下载到本地。
- Provider 的限制放在适配器中，不写死到通用数据表。
- 所有文字模型输出必须经过 Pydantic 校验。
- 图片和视频每次重新生成都插入新版本，不覆盖旧文件。
- 长耗时视频任务保存服务商 task_id，程序重启后继续轮询。
- 上游变化通过输入签名判断下游是否过期，不做递归状态传播。

## 五、Provider 设计

V1 只有三类 Provider。

### 5.1 通用配置

每个 Provider 配置包含：

```python
class ProviderConfig(BaseModel):
    id: str
    kind: Literal["text", "image", "video"]
    name: str
    adapter: str
    base_url: str = ""
    api_key_env: str = ""
    model: str
    params: dict = {}
    timeout_sec: int = 120
    max_retries: int = 2
    enabled: bool = True
```

API Key 只从环境变量读取：

```env
TEXT_API_KEY=sk-xxx
IMAGE_API_KEY=sk-xxx
VIDEO_API_KEY=sk-xxx
```

数据库只保存环境变量名称，不保存密钥正文。

### 5.2 Text Provider

统一接口：

```python
class TextProvider(Protocol):
    async def generate_json(
        self,
        *,
        system_prompt: str,
        user_prompt: str,
        schema: type[BaseModel],
        params: dict,
    ) -> BaseModel: ...
```

默认先实现 OpenAI-compatible Adapter。

文字任务包括：

- `analyze_novel`
- `generate_screenplay`
- `extract_assets`
- `generate_asset_prompt`
- `extract_shots`
- `generate_shot_image_prompt`
- `generate_shot_video_prompt`

#### 结构化输出处理

1. 要求模型输出 JSON。
2. 使用 Pydantic 校验。
3. 校验失败时，将错误信息连同原响应交给模型修复一次。
4. 第二次仍失败则任务失败并保留原始响应摘要。
5. 不允许把无法解析的字符串直接写入业务表。

### 5.3 Image Provider

统一接口：

```python
class ImageProvider(Protocol):
    async def submit(
        self,
        *,
        prompt: str,
        negative_prompt: str,
        reference_files: list[Path],
        params: dict,
    ) -> "ProviderSubmission": ...

    async def poll(self, task_id: str) -> "ProviderPollResult": ...

    async def download(self, result: "ProviderPollResult", target: Path) -> Path: ...
```

适配器必须兼容两种模式：

- 同步返回图片结果。
- 异步返回 task_id 后轮询。

图片 Provider 的模型限制，例如最大参考图数量、尺寸枚举、是否支持负向提示词，由 Adapter 校验。

### 5.4 Video Provider

统一接口：

```python
class VideoProvider(Protocol):
    async def prepare_input_image(self, local_file: Path) -> dict: ...

    async def submit(
        self,
        *,
        prompt: str,
        input_image: dict,
        duration_sec: float,
        params: dict,
    ) -> "ProviderSubmission": ...

    async def poll(self, task_id: str) -> "ProviderPollResult": ...

    async def download(self, result: "ProviderPollResult", target: Path) -> Path: ...
```

`prepare_input_image()` 由具体 Adapter 处理：

- 上传本地文件并返回服务商 file_id。
- 转为 Base64。
- 上传到服务商临时空间并返回 URL。
- 使用用户配置的临时上传接口。

平台通用业务层不假设视频接口一定接收公网 URL。

#### Provider 限制不能写死在数据库

例如某视频模型可能要求：

- 时长 6–30 秒整数。
- 最多 7 张参考图。
- 只接受公网 URL。
- 只支持 720p。

这些只能写在对应 Adapter 的 `validate_request()` 中。其他模型可以拥有不同规则。

## 七、数据模型

V1 使用 9 类业务实体表，加 1 张通用 Job 表，共 10 张实际表；不建立重复 Job 表、步骤状态表、配音表或合成表。

### 7.1 `project`

```sql
CREATE TABLE project (
    id                    TEXT PRIMARY KEY,
    name                  TEXT NOT NULL,
    source_text           TEXT NOT NULL DEFAULT '',
    source_signature      TEXT NOT NULL DEFAULT '',
    source_revision       INTEGER NOT NULL DEFAULT 1,
    style_prompt          TEXT NOT NULL DEFAULT '',
    aspect_ratio          TEXT NOT NULL DEFAULT '16:9',
    image_size            TEXT NOT NULL DEFAULT '1920x1080',
    video_size            TEXT NOT NULL DEFAULT '16:9',
    default_duration_sec  REAL NOT NULL DEFAULT 6,
    default_text_provider_id  TEXT,
    default_image_provider_id TEXT,
    default_video_provider_id TEXT,
    created_at            TEXT NOT NULL,
    updated_at            TEXT NOT NULL
);
```

小说正文变化时：

```text
source_revision += 1
source_signature = sha256(normalized_source_text)
```

### 7.2 `api_provider`

```sql
CREATE TABLE api_provider (
```

```sql

    expressions_json        TEXT NOT NULL DEFAULT '[]',
    dialogue_json           TEXT NOT NULL DEFAULT '[]',
    narration               TEXT NOT NULL DEFAULT '',
    shot_type               TEXT NOT NULL DEFAULT '',
    camera_angle            TEXT NOT NULL DEFAULT '',
    camera_move             TEXT NOT NULL DEFAULT '',
    duration_sec            REAL NOT NULL DEFAULT 6,
    end_state               TEXT NOT NULL DEFAULT '',
    next_hook               TEXT NOT NULL DEFAULT '',
    frame_description       TEXT NOT NULL DEFAULT '',
    image_prompt            TEXT NOT NULL DEFAULT '',
    video_prompt            TEXT NOT NULL DEFAULT '',
    negative_prompt         TEXT NOT NULL DEFAULT '',
    reference_bindings_json TEXT NOT NULL DEFAULT '[]',
    status                  TEXT NOT NULL DEFAULT 'draft'
                            CHECK (status IN ('draft','ready','confirmed','failed')),
    own_signature           TEXT NOT NULL DEFAULT '',
    revision                INTEGER NOT NULL DEFAULT 1,

```

`reference_bindings_json` 示例：

```json
[
  {
    "role": "character_identity",
    "asset_id": "char-1",
    "asset_image_id": "img-1"
  },
  {
    "role": "scene_layout",
    "asset_id": "scene-1",
    "asset_image_id": "img-8"
  },
  {
    "role": "previous_keyframe",
    "keyframe_id": "kf-10"
  }
]
```

不依赖数组下标猜测职责，也不把不同类型的 ID 混成一个 `asset_id` 数组。

```sql
    status                   TEXT NOT NULL DEFAULT 'queued'
                             CHECK (status IN ('queued','running','waiting_provider','downloading','completed','failed')),
    is_current               INTEGER NOT NULL DEFAULT 0,
    input_signature          TEXT NOT NULL DEFAULT '',
    source                   TEXT NOT NULL DEFAULT 'generated'
                             CHECK (source IN ('generated','uploaded')),
    cost_estimate            REAL NOT NULL DEFAULT 0,
    error                    TEXT NOT NULL DEFAULT '',
    created_at               TEXT NOT NULL,

ON video_version(shot_id)
```

## 八、签名与失效判断

V1 不存递归 `stale` 状态，只存生成时的 `input_signature`。

### 8.1 签名规则

```text
project.source_signature
    = sha256(小说正文)

screenplay.own_signature
    = sha256(剧本 JSON)

asset.own_signature
    = sha256(profile_json + prompt + negative_prompt + 项目画风)

shot.own_signature
    = sha256(分镜语义字段 + image_prompt + video_prompt + negative_prompt)

asset_image.input_signature
    = sha256(asset.own_signature + provider + model + params + reference_files)

keyframe.input_signature
    = sha256(shot.own_signature + reference_bindings + provider + model + params)

video.input_signature
    = sha256(keyframe_version_id + shot.video_prompt + duration + provider + model + params)
```

### 8.2 判断逻辑

查询媒体列表时重新计算当前输入签名：

```python
def is_stale(saved_signature: str, current_signature: str) -> bool:
    return saved_signature != current_signature
```

失效只影响 UI 提示：

- 旧文件仍然可预览。
- 当前版本仍然保留。
- 用户可以继续使用。
- 用户可以点击重新生成。
- 不执行递归 UPDATE。

## 九、提示词编译

### 9.1 项目统一画风

所有图片提示词和视频提示词都先注入：

```text
项目画风 + 画面比例 + 基础质量要求
```

统一画风只在项目中维护一份，避免角色、场景和分镜各自漂移。

### 9.2 素材提示词

素材提示词由文字模型生成，但提交图片模型前由编译器拼装：

```python
render_prompt = join_non_empty([
    project.style_prompt,
    asset.prompt,
    consistency_keywords,
    asset.composition,
])
```

### 9.3 分镜关键帧提示词

```python
render_prompt = join_non_empty([
    project.style_prompt,
    shot.image_prompt,
    resolved_character_anchors,
    resolved_scene_description,
    resolved_prop_descriptions,
    continuity_instruction,
])
```

参考图无法找到时：

- 记录 warning。
- 在页面显示缺失项。
- 用户仍可选择只用文字生成。

### 9.4 分镜视频提示词

视频提示词由文字模型生成后直接允许用户编辑。提交 Provider 前追加确定性信息：

- 实际时长
- 关键帧职责
- 角色身份参考职责
- 禁止随机新增人物
- 禁止服装和物品漂移

Provider Adapter 可以按照特定模型语法做最后转换，但不能覆盖用户编辑的核心动作内容。

## 十、任务系统

### 10.1 job_type

```text
analyze_novel
generate_screenplay
extract_assets
generate_asset_prompt
generate_asset_image
extract_shots
generate_shot_image_prompt
generate_shot_video_prompt
generate_keyframe
generate_video
```

### 10.2 并发

本地默认并发：

```python
WORKER_LIMITS = {
    "text": 1,
    "image": 2,
    "video": 1,
}
```

用户可在配置中调整，但不能小于 1。

### 10.3 批量任务

批量操作创建一个 `batch_id`，每个目标创建独立 Job：

```text
批量生成 20 张关键帧
→ 创建 20 个 generate_keyframe Job
→ 共用一个 batch_id
```

优点：

- 单项失败不影响其他项。
- 可以只重试失败项。
- 每个分镜有独立进度和错误信息。
- 不需要父任务表和复杂子任务状态机。

前端按 `batch_id` 汇总成功、失败和总数。

### 10.4 重启恢复

应用启动时扫描非终态 Job：

```text
queued
→ 重新入队

waiting_provider 且 provider_task_id 非空
→ 继续轮询原任务

running 且没有 provider_task_id
→ 标记 interrupted，用户手动重试

downloading 且结果 URL 仍在 input/result JSON 中
→ 尝试继续下载；失败则标记 failed
```

绝不在无法判断是否已提交付费任务时自动重新提交。

### 10.5 SQLite 多线程规则

- 开启 `PRAGMA journal_mode=WAL`。
- 开启 `PRAGMA foreign_keys=ON`。
- 设置 `PRAGMA busy_timeout=5000`。
- 每个线程使用独立连接。
- 外部 API 调用期间不持有数据库事务。
- 写入使用短事务。
- 切换 `is_current` 必须在一个事务中完成：先清零旧版本，再设置新版本。

```text

→ 写入本地文件
```

不能在页面播放时才下载。

- 删除失败任务产生的临时文件。
- 清空项目 temp 目录。

当前版本删除前必须先选择其他版本或取消当前版本。

## 十四、错误处理

### 14.1 文字模型错误

- HTTP 错误：按配置重试。
- JSON 格式错误：执行一次结构修复请求。
- Pydantic 校验错误：显示具体字段。
- 内容为空：任务失败，不覆盖现有内容。

### 14.2 图片模型错误

- 提交失败：记录响应摘要。
- 参考图不支持：Adapter 返回明确错误。
- 结果 URL 下载失败：保留 task_id 和 URL，允许重试下载。
- 图片为空或无法解码：版本状态标记 failed。

### 14.3 视频模型错误

- 参数不符合模型限制：提交前由 Adapter 阻断。
- 任务失败：保存服务商错误。
- 轮询超时：保持 task_id，用户可以继续查询。
- 结果下载失败：不重新生成，只重试下载。
- 视频无法解码：版本标记 failed。

## 十六、测试策略

### 16.1 后端核心测试

| 主题 | 必测场景 |
|---|---|
| 小说修订 | 修改正文后 source_signature 和 revision 变化 |
| JSON 校验 | 合法输出成功；缺字段触发修复；修复失败不覆盖旧内容 |
| 素材提取 | 角色、场景、物品可分别落库；重复名称拒绝或合并 |
| 分镜来源 | novel 和 screenplay 两种来源签名正确 |

## 十七、V1 完成定义

只有满足以下条件才算完成：

- 三类 Provider 可以独立配置和测试。
- 文字模型所有输出均有结构化 Schema。
- 小说可以生成分析、剧本和素材。
- 分镜可以从小说或剧本生成。
- 角色、场景、物品、分镜图像和分镜视频提示词可编辑。
- 图片接口可以生成素材图和关键帧。

- 批量任务允许部分失败。
- 视频异步任务可以在程序重启后继续查询。
- 文档中不存在重复表定义、未定义字段或相互冲突的流程。
