# 画风、素材完整性、文字推理强度与平台存储设置补全设计

## 目标

在不改变现有剧本生成、手工修改统一画风及后续素材画风传递逻辑的前提下，完成以下四项修复：

1. 使用用户提供的完整系统提示词和用户提示词，将自动画风压缩到 18 至 32 个字符。
2. 素材提取只保留影响剧情或多次出场的关键角色；律师、前台、助理等临时角色不创建素材，也不阻塞分镜提取。
3. 所有 OpenAI-compatible 文字模型请求统一使用 `reasoning_effort: xhigh`。
4. 完成平台项目存储目录设置，使设置可加载、可选择，并立即影响之后新建的项目；已有项目路径保持不变。

## 已确认根因

### 自动画风过长

当前 `visual_style.md` 明确要求输出 60 至 180 个汉字，`VisualStyleOutput` 也允许最多 300 个字符，与用户要求的 18 至 32 个字符冲突。当前调用虽然区分 system 和 user 消息，但 user 内容不是用户提供的完整用户提示词。

### 分镜角色素材缺失

素材提取原有核心原则是只提取“影响剧情或多次出场者”，律师、前台、张助理、女助理等单场角色不应进入素材库。问题实际来自分镜提取把所有 `character_names` 都当成必须绑定的素材，导致临时角色缺少素材时阻断整批分镜。

### 文字模型未指定推理强度

OpenAI-compatible 文字 Provider 直接合并配置参数与调用参数，没有统一写入 `reasoning_effort`，因此每个请求的推理强度取决于 Provider 默认行为。

### 平台设置开发未收尾

前端页面、API 客户端、设置服务和数据库字段已经存在，但主应用没有注册 settings 路由，所以页面请求返回 404。除此之外，文件服务仍在启动时固定全局目录，项目创建也没有持久化 `storage_root/storage_layout`，仅注册路由会形成“设置显示成功但新项目仍写旧目录”的假完成。

## 设计

### 1. 画风提示词与输出约束

将 `D:\LyProject\Other\画风提示词.txt` 中的两段内容原样内置为两个项目模板：

- `visual_style.md`：仅保存完整系统提示词。
- `visual_style_user.md`：保存完整用户提示词，并保留一个明确的正文占位符。

画风调用继续作为“生成完整剧本”中的独立文字模型请求：

1. `system_prompt` 加载 `visual_style.md`。
2. `user_prompt` 加载 `visual_style_user.md`，只将正文占位符替换为当前小说正文。
3. 画风请求发送原样 system/user 两条消息，不追加 JSON Schema 或 `response_format`；模型返回的一句纯文本包装为 `style_prompt`，再由 `VisualStyleOutput` 的 18 至 32 字约束校验首次输出和修复输出。
4. 识别成功后仍覆盖点击前输入框中的默认值或用户值；任务执行期间用户再次手工修改时，继续保留现有并发保护，不覆盖新值。
5. 后续素材、关键帧和视频继续读取项目当前 `style_prompt`，不改变既有 STYLE_ANCHOR 传递链路。

外部 `画风提示词.txt` 只作为本次需求来源，不成为运行时依赖，避免项目换目录或部署后无法读取。

### 2. 关键角色素材与分镜绑定

素材提取仍由用户在素材库执行，不在分镜阶段创建资料不完整的临时角色。

素材提取只提交小说正文，并在系统提示词中明确：角色仅包含影响剧情或多次出场、需要长期保持身份一致性的关键人物。仅承担一次性功能的律师、前台、助理等临时角色，以及群众、路人等背景人物，不单独创建角色素材，也不执行全角色二次补齐调用。

素材入库继续沿用现有按“项目 + 类型 + 名称”更新逻辑，已确认素材不被自动覆盖。分镜提取以当前素材目录为绑定源：素材库中已有的关键角色继续按 ID、名称或别名准确绑定；没有独立素材的临时角色保留在动作、对白、站位及提示词文本中，但不写入 `character_ids`，也不因缺少素材阻断分镜保存。

场景和重要物品仍保持现有绑定校验。角色请求提供未知素材 ID，或提供的角色 ID 与名称不一致时仍返回错误，避免把关键角色错误绑定到其他素材。

### 3. 文字模型统一使用 xhigh 推理强度

在 `OpenAICompatibleTextProvider._complete()` 的请求载荷层统一设置：

```json
{"reasoning_effort": "xhigh"}
```

该值在 Provider 配置和单次调用参数合并后写入，因此调用方不能降级覆盖。首次结构化输出和校验失败后的修复调用都会经过同一入口。Mock Provider 不发送 HTTP 请求，无需模拟该参数；图片和视频 Provider 不受影响。

### 4. 平台存储设置完整闭环

#### 路由与设置保存

- 在主 FastAPI 应用中注册 settings 路由，使 `GET /api/settings/project-storage` 和 `POST /api/settings/project-storage/select` 可用。
- 保留现有 Windows 原生目录选择框、安全校验、可写性探测、取消不修改和中文错误反馈。
- 数据库设置优先级保持为：数据库 `project_storage_root` > `APP_PROJECTS_DIR` > `workspace/projects`。

#### 新项目目录

新建项目时动态读取当前有效根目录，不要求重启。项目目录使用清洗后的项目名；同名时以原子目录创建依次尝试 `项目名`、`项目名 (2)`、`项目名 (3)`。

项目记录持久化：

- `storage_root`：创建时使用的绝对根目录；
- `storage_name`：实际创建的项目目录名；
- `storage_layout`：新项目为 `categorized`。

新项目目录内创建 `角色`、`物品`、`场景`、`分镜关键帧`、`分镜视频` 五个分类目录。数据库写入失败时，只清理本次原子预留的空项目目录，不触碰已有同名目录。

#### 旧项目兼容与媒体访问

文件服务绑定当前数据库，并在每次解析项目路径时读取该项目持久化的存储字段：

- `categorized`：`storage_root / storage_name`；
- `prefixed`：`storage_root / project_id`，继续使用旧版带项目前缀的分类目录。

`/media/{project_id}/{relative_path}` 不再依赖启动时固定的单一静态目录，而是按项目记录动态解析。访问必须拒绝绝对路径、`..`、未知项目和越界路径，只返回该项目目录内的真实文件。

更换平台根目录只影响之后新建的项目；已有项目不搬迁、不改记录。删除项目只允许删除记录对应根目录的直接子目录，安全校验失败时保留数据库记录和磁盘内容并返回错误。

## 错误处理

- 画风输出不满足 18 至 32 字时，由纯文本修复流程重试；仍失败则保留原画风并继续生成剧本。
- 分镜中的临时角色没有素材时继续保存分镜；角色素材 ID 无效或与名称不一致时返回明确错误。
- 目录选择取消时返回当前目录，不显示错误。
- 目录不安全、不可写或过深时保留原设置并返回可执行的中文提示。
- 项目目录创建或数据库写入失败时，只回滚本次创建的目录。

## 测试与验收

### 后端

- 断言画风调用分别使用完整 system/user 模板，正文只替换指定占位符。
- 断言画风字段接受 18 至 32 字、拒绝过短和过长值。
- 断言剧本包含律师、前台和助理等临时角色时，素材提取仍只调用一次并只保存模型识别出的关键角色。
- 断言同一分镜包含关键角色和临时角色时成功保存，只将已有关键角色写入 `character_ids`。
- 断言场景、重要物品、未知角色素材 ID 及角色 ID/名称不一致仍会阻止错误绑定。
- 断言所有 OpenAI-compatible 文字请求及修复请求载荷都包含 `reasoning_effort: xhigh`，调用参数不能覆盖。
- 断言主应用平台设置 GET/POST 路由可访问。
- 运行并通过现有 `test_project_storage_settings.py`、`test_project_storage_paths.py` 以及动态媒体路由相关测试。

### 前端

- 平台设置页面能加载当前目录。
- 选择成功、取消、失败和 pending 状态测试通过。
- API 客户端测试、相关页面测试、前端构建和 lint 通过。

### 真实运行验证

重启项目后验证：

1. `GET /api/settings/project-storage` 返回 200。
2. 新建项目使用新选择的目录，旧项目仍从原目录读取。
3. “生成完整剧本”回填 18 至 32 字画风且允许后续手工修改。
4. 重新提取素材后只保留关键角色；包含律师、前台、张助理、女助理等临时角色的分镜仍能正常提取，并准确绑定已有关键素材。

## 不包含

- 不自动搬迁已有项目。
- 不在分镜阶段创建无完整设定的占位角色素材。
- 不为临时角色创建占位素材；只放宽“没有素材的角色名称”，不放宽错误素材 ID 或 ID/名称不一致校验。
- 不改变图片和视频 Provider 的推理参数。
- 不创建 commit、push 或 PR。
