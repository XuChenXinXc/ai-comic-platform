# 失败媒体删除与项目媒体扁平化设计

## 目标

1. 图片生成失败记录点击删除后立即删除，不再显示“删除图片”确认框；正常图片和视频文件仍保留原确认流程。
2. 新式项目目录继续按媒体类型分类，但分类目录下不再创建素材 ID 或分镜 ID 子目录。
3. 当前版本使用可读文件名，历史版本追加版本号；迁移现有新式项目中的媒体文件和数据库路径，不覆盖或丢失历史版本。

## 采用方案

在保留多版本能力的前提下使用“当前版简洁名、历史版带版本号”的扁平结构。相比所有文件都带版本号，此方案符合用户直接查看当前成品的习惯；相比只保留一个固定文件名，不会破坏历史版本。

```text
测试文章/
├── 角色/
│   ├── 角色-林舟.png
│   └── 角色-林舟-v001.png
├── 物品/
│   └── 物品-银色怀表.png
├── 场景/
│   └── 场景-青石巷雨夜.png
├── 分镜图/
│   └── 分镜图-001.png
└── 分镜视频/
    └── 分镜视频-001.mp4
```

文件扩展名保留实际媒体格式，不把 PNG 强制转码成 JPG。

## 删除交互

- 素材图片和分镜关键帧的 `failed` 版本只是失败记录，没有可删除的媒体文件，点击垃圾桶后直接调用删除接口。
- 已完成的非当前图片仍显示现有确认框。
- 视频删除交互不在本次修改范围内，保持现状。
- 删除请求失败时继续使用现有错误提示；请求期间沿用按钮忙碌状态，防止重复点击。

## 文件命名与版本切换

- 素材当前版：`<分类>/<分类>-<素材名>.<ext>`。
- 素材历史版：`<分类>/<分类>-<素材名>-vNNN.<ext>`。
- 分镜图当前版：`分镜图/分镜图-<三位分镜号>.<ext>`。
- 分镜图历史版：`分镜图/分镜图-<三位分镜号>-vNNN.<ext>`。
- 分镜视频沿用相同规则，扩展名通常为 `.mp4`。
- 新版本完成或上传成功时，先把旧当前文件改为其历史版本名，再把新版本设为简洁名，并同步数据库 `file_path`。
- 用户切换当前版本时，对两个文件执行相反的名称切换，并在同一业务操作中更新数据库路径与 `is_current`。
- 失败版本没有文件，不参与重命名。

文件名中的 Windows 非法字符继续使用现有清洗规则处理。若同类素材名称在清洗、截断或忽略大小写后重名，仅对冲突素材在可读名称后追加稳定短标识；普通名称仍保持 `角色-林舟.jpg`。上传和生成结果先写入该版本独占的临时文件，再以拒绝覆盖的方式移入正式目录；失败清理只删除本次创建的临时文件或目标文件。

## 现有项目迁移

- 仅迁移 `categorized` 新式布局；旧式 `prefixed` 项目继续保持兼容，避免破坏历史目录。
- 按数据库中的素材名称、分镜号、版本号、当前状态和真实扩展名计算目标路径。
- 当前版本迁移到简洁名，非当前成功版本迁移到带版本号的文件名。
- 使用按媒体记录固定的暂存路径移动文件，数据库路径只在对应文件成功移动后更新；进程在暂存阶段或数据库提交前中断时，下次启动根据源文件、暂存文件和目标文件的位置继续迁移。
- 任一步正常失败时回滚本次已移动文件，不删除原文件；单个项目迁移异常会记录错误并跳过，不阻止平台启动。
- 全部媒体迁移成功后，移除已经为空的素材 ID/分镜 ID 目录，并把空的 `分镜关键帧` 目录替换为 `分镜图`。
- 缺失文件不伪造；保留原数据库记录并报告迁移失败，防止静默丢失。

## 测试与验收

- 前端回归测试：失败素材图和失败关键帧点击删除不调用 `window.confirm`，已完成图片仍调用确认框。
- 文件服务测试：三类素材、分镜图和分镜视频均生成扁平、可读且带正确版本语义的路径。
- 媒体服务测试：生成完成、上传、切换当前版本、删除历史版本后，文件和数据库路径一致。
- 迁移测试：现有 ID 子目录被安全迁移；多版本、中文名、不同扩展名和失败记录处理正确；目标冲突时不覆盖原文件；硬中断后可在下次启动恢复。
- 定向测试通过后运行后端完整 pytest、前端单元测试与类型/构建检查。

## 不包含

- 不转码图片或视频格式。
- 不修改旧式 `prefixed` 项目的目录布局。
- 不创建 commit、push 或 PR。
