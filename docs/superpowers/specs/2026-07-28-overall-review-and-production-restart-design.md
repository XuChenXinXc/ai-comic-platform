# 整体审查与生产一键重启设计

## 目标

在不改变 V1 产品边界的前提下，修复本轮审查中已复现的高、中风险问题，并提供可双击的生产模式一键重启入口。

成功标准：

1. 双击 `一键启动.cmd` 后，先安全停止本项目已有开发或生产进程，再启动新的生产单进程。
2. 只终止可验证属于当前项目的进程；陈旧状态或未知程序占用端口时不得误杀。
3. 数据库迁移、进程启动和 `/api/health` 均成功后才打开浏览器并报告成功。
4. 启动失败保留日志、清理本次状态，并返回非零退出码。
5. 本轮已复现的后端、前端问题均有自动化回归测试。

## 选定方案

采用受控后台重启：

- `一键启动.cmd`：Windows 双击入口。优先调用 `pwsh.exe`，缺失时回退到 `powershell.exe`；成功自动关闭，失败暂停显示错误。
- `restart.ps1`：获取项目专属 Mutex，调用安全停止流程，执行数据库迁移，启动隐藏的生产 Uvicorn，原子写入运行状态，轮询健康接口，成功后打开浏览器。
- `.run/platform.state.json`：保存 schema、项目根目录、模式、PID、UTC
  启动时间与 ticks、可执行文件、命令行、主机和端口；ticks 用于保证
  Windows PowerShell 5.1 与 PowerShell 7 交叉启停时的身份校验一致。
- `.run/platform.stdout.log` 与 `.run/platform.stderr.log`：保存生产进程日志。
- `stop.ps1`：校验状态中的项目路径、可执行文件、启动时间和命令行后，再由内向外停止进程树；等待进程和端口释放。无效状态只清理状态文件。

Mutex 只用于同一项目目录的启停操作，避免并发双击互相覆盖状态。

## 启动数据流

```text
双击一键启动
→ 核验后端虚拟环境，以具备旧进程身份验证能力
→ 获取项目 Mutex
→ 读取并校验运行状态
→ 停止已验证属于本项目的旧进程树
→ 等待旧进程和监听端口释放
→ 检查前端生产构建、FFmpeg 与运行配置
→ 执行 Alembic migration
→ 从项目配置读取 host/port
→ 启动生产 Uvicorn 并写原子状态
→ 轮询进程存活与 /api/health
→ 成功后打开浏览器
```

虚拟环境缺失时无法可靠核验旧 Python 进程身份，因此会在停止旧实例前安全退出。
若端口由未知程序占用，启动立即失败并显示占用 PID，不按端口强杀。

## 审查修复范围

### 启动与工具脚本

- 防止陈旧 PID 误杀无关进程。
- 修复重复开发启动、部分启动失败产生孤儿进程、未就绪即打开浏览器。
- 原生命令执行后检查 `$LASTEXITCODE`，避免 setup/build/check 假报成功。
- 启动脚本统一使用 `.env` 中的合法 host/port 配置。

### 后端

- 下载阶段恢复识别嵌套的 `result_data.data.local_file`。
- 取消排队任务时同步媒体或写作目标状态。
- 删除关键帧前阻止破坏活动视频任务或上一镜关键帧引用。
- 可恢复任务通过数据库原子状态转换后再由单 worker claim，避免多进程重复执行。
- Provider `base_url` 拒绝 URL userinfo 与敏感查询参数。

### 前端

- 任务完成时不覆盖用户尚未保存的分析或剧本编辑。
- 切换项目时清空素材、分镜、素材图、关键帧和视频批量选择。
- 素材提示词与分镜提示词批处理展示入队数、跳过数和逐项失败原因。

## 错误处理

- 虚拟环境缺失：在停止旧实例前提示运行 `setup.ps1`，不自动安装。
- 前端构建或 FFmpeg 缺失：先按重启语义停止旧实例，再提示修复依赖，不启动新实例。
- 数据库迁移失败：不启动服务，保留错误输出。
- 服务秒退或健康检查超时：停止本次创建且身份匹配的进程，删除状态，显示日志末尾。
- 浏览器打开失败：服务继续运行并显示访问 URL。
- 停止失败：保留状态文件并返回非零退出码，避免失去追踪。

## 验证

自动化：

- 后端新增恢复、取消、关键帧引用、原子恢复 claim、Provider URL 校验测试。
- 前端新增编辑冲突、跨项目选择、两类批量反馈测试。
- 现有 `check.ps1`、pytest、Vitest、TypeScript、ESLint、ruff 全量通过。

进程生命周期：

1. 首次启动：健康接口成功，状态 PID 等于 8000 监听进程。
2. 连续两次启动：旧 PID 退出，新 PID 唯一且健康。
3. 陈旧状态指向无关进程：无关进程仍存活。
4. 未知程序占用配置端口：一键启动失败，占用程序仍存活。
5. 停止：状态、进程树和监听端口全部释放。
6. 并发启动：最终只有一个受控实例。
7. 跨版本启停：PowerShell 5.1 创建的状态可由 PowerShell 7 安全重启，
   PowerShell 7 创建的状态也可由 PowerShell 5.1 安全停止。

## 非目标

- 不新增配音、字幕、BGM 或最终合成功能。
- 不自动安装依赖或自动构建缺失的生产前端。
- 不强制修改当前不使用 React Router unstable RSC API 的依赖版本。
- 不创建 commit、push 或 PR。
