# 全局任务状态与分镜视频一体化设计

日期：2026-07-29

## 1. 目标

本次改动解决两个问题：

1. 所有持久化后台任务在任意业务页面顶部都有持续、可理解的 Loading 状态。
2. 将“分镜与提示词”“分镜关键帧”“分镜视频”三个生产入口合并为一个“分镜视频”入口，在同一页面完成分镜提取、提示词维护、关键帧生成和视频生成。

改动必须保留现有分镜编辑、结构调整、批量范围、媒体版本、上传替换、导出、任务诊断和失败恢复能力。

## 2. 范围与约定

### 2.1 本次范围

- 在应用主内容顶部增加全局任务状态条。
- 统一分镜、关键帧、视频的导航入口、选择状态和批量操作。
- 同一分镜卡片内展示分镜信息、关键帧和视频三个生产阶段。
- 支持单个、选中项、指定场次和全部关键帧生成。
- 支持单个、选中项、指定场次和全部视频生成。
- 保留旧 `/keyframes`、`/videos` 地址的兼容跳转。
- 为缺失专业提示词的分镜提供确定性降级提示词，使提取后可以直接发起关键帧或视频生成。
- 更新相关前端单元测试和 Playwright 端到端测试；为后端降级提示词补充 pytest 回归测试。

### 2.2 语义约定

- 用户描述中的“从当前分镜提取”按当前系统已有能力解释为“从当前剧本提取”。
- “所有任务”指通过后端 Job 系统持久化的后台任务，包括小说分析、剧本生成、素材提取、提示词、素材图、分镜提取、关键帧和视频任务。
- 保存、删除、上传、切换版本、下载、导出等短请求继续使用原有按钮 Loading，不进入全局任务状态条，避免普通请求导致页面顶部频繁闪烁。

### 2.3 非目标

- 不新增数据库表或迁移。
- 不改变 Provider 配置、任务重试、取消和恢复协议。
- 不新增自动生成全部成片、配音、字幕、BGM 或最终合成能力。
- 不新增跨任务依赖调度器，不自动串行调用“提示词生成 → 关键帧生成 → 视频生成”。
- 不删除媒体版本、上传替换、下载、ZIP 导出等已有能力。

## 3. 当前实现约束

- `AppShell` 已调用 `useJobPolling(activeProjectId)`，可以直接取得当前项目的任务列表和活动任务数量。
- Job 已包含 `status`、`progress_current`、`progress_total`、`message`、`batch_id` 等字段。
- 活动状态包括 `queued`、`running`、`waiting_provider` 和 `downloading`。
- 三个现有页面已经分别实现分镜维护、关键帧管理和视频管理，后端接口无需合并。
- 分镜提取保存时会将 `image_prompt`、`video_prompt` 和 `negative_prompt` 置空，提取后的分镜只有 `frame_description`、`action`、起止状态、运镜和时长等结构化信息。

## 4. 方案选择

采用“单一导航入口 + 统一流水线页面 + 可复用任务状态条”。

不采用仅把原页面放入内部子 Tab 的方案，因为用户仍需理解三个页面之间的依赖关系；不采用把三个完整页面直接纵向拼接的方案，因为会造成重复查询、重复选择状态和重复批量控制。

统一页面共享一份：

- 当前项目分镜列表；
- 素材映射；
- 选中分镜集合；
- 批量范围；
- Job 状态；
- 批量成功、跳过和失败反馈。

## 5. 导航与路由

生产导航调整为五个入口：

1. 项目小说
2. 小说分析与剧本
3. 素材与提示词
4. 素材图片
5. 分镜视频

“接口配置”和“任务中心”继续作为独立管理入口。

路由策略：

- `/shots` 为统一“分镜视频”页面的标准地址。
- `/keyframes` 跳转到 `/shots?stage=keyframes`。
- `/videos` 跳转到 `/shots?stage=videos`。
- `stage` 参数只负责把用户定位到页面内对应区域，不恢复成独立业务页面。

## 6. 全局任务状态条

### 6.1 位置

任务状态条放在 `AppShell` 主内容容器内、业务页面 `Outlet` 之前。桌面和窄屏均位于页面内容顶部，并使用 sticky 布局保持任务执行期间可见，不覆盖侧栏或页面操作。

### 6.2 展示规则

- 当前项目没有活动 Job 时隐藏。
- 一个活动 Job 时显示任务名称、目标、业务状态、Job 消息和进度。
- 多个活动 Job 时显示活动数量和汇总状态。
- 有可计算进度时显示确定进度；当前进度无法反映真实完成比例时显示动画进度，避免把执行中的任务错误表现为长期 0%。
- 点击状态条进入任务中心。
- 原有侧栏任务数量角标和各按钮 `busy` 状态继续保留。

### 6.3 批量进度

同一 `batch_id` 的任务按以下方式汇总：

- 总数：该批次全部 Job 数量。
- 已处理：`completed`、`failed`、`cancelled`、`interrupted` 的数量。
- 活动中：`queued`、`running`、`waiting_provider`、`downloading` 的数量。
- 批量任务存在失败时，不显示为全部成功；详细失败信息仍在任务中心查看。

多个互不相关的活动任务不虚构统一百分比，只显示活动数量和动画进度。

### 6.4 可复用边界

新增公共任务名称映射，供任务状态条和任务中心共同使用。以后增加新 Job 类型时，只需补充名称映射，不需要在每个页面实现独立 Loading。

任务状态条只消费 Job 列表，不自行请求接口；轮询仍由 `useJobPolling` 统一负责。

## 7. 分镜视频统一页面

### 7.1 页面顶部操作区

页面标题为“分镜视频”，顶部操作分为两组：

第一组负责分镜来源和维护：

- 从小说提取；
- 从当前剧本提取；
- 提取或重新提取全部；
- 手工新增。

第二组负责生产：

- 补齐提示词；
- 生成关键帧；
- 生成视频；
- 导出当前版本 ZIP。

批量目标遵循固定优先级：

1. 已勾选分镜；
2. 指定场次；
3. 全部分镜。

同一份勾选集合同时服务于提示词、关键帧和视频批量操作，避免三个页面之间重复选择。

### 7.2 页面概览

操作区下方显示：

- 分镜总数；
- 已具备专业图片提示词的分镜数；
- 已有当前完成关键帧的分镜数；
- 已有当前完成视频的分镜数。

概览只用于反馈当前完成度，不引入新的后端统计接口。

### 7.3 单分镜流水线卡片

每个分镜使用一张卡片，按顺序包含三个区域。

#### 分镜与提示词

保留：

- 分镜编号、场景、角色、物品、动作、对白、旁白、起止状态和连续性信息；
- 编辑、确认、上移、下移、拖动排序；
- 拆分、复制、合并、删除；
- 按场次重生成；
- 单独生成图片提示词和视频提示词；
- 保存图片提示词、视频提示词和负向提示词；
- 来源变化和媒体过期提示。

#### 关键帧

保留：

- 当前关键帧预览；
- 单个生成新版本；
- 上传替换；
- 版本列表；
- 设为当前版本；
- 删除版本；
- 来源变化提示；
- 缺少素材参考图时的纯文字降级提示。

#### 视频

保留：

- 当前视频播放；
- 单个生成新版本；
- 上传替换；
- 版本列表；
- 设为当前版本；
- 删除版本；
- 单个视频下载；
- 缺少已完成当前关键帧时的禁用状态和可执行说明。

桌面宽屏先显示全宽分镜信息，再在下方以左右两列展示关键帧和视频；窄屏按分镜、关键帧、视频顺序纵向排列。当前版本始终可见，历史版本沿用现有横向版本列表。

## 8. 提示词降级策略

专业提示词生成能力继续保留，专业提示词优先级最高。

关键帧：

- `image_prompt` 非空时使用原值。
- `image_prompt` 为空时使用 `frame_description`。
- 两者都为空时拒绝生成，并返回明确的“缺少关键帧画面描述”错误。

视频：

- `video_prompt` 非空时使用原值。
- `video_prompt` 为空时，按固定顺序组合 `start_state`、`action`、`end_state`、`camera_move` 和 `duration_sec`。
- 组合后仍没有有效动作内容时拒绝生成，并返回明确的“缺少视频动作描述”错误。

该策略不触发额外文字 Provider 调用，用户可在需要更高质量时主动使用“补齐提示词”。

前端对降级生成给出轻量提示，但不增加阻断弹窗。

## 9. 数据流

### 9.1 分镜提取

1. 用户选择小说或当前剧本。
2. 页面调用现有分镜提取接口。
3. 返回 Job 后刷新当前项目 Job 查询。
4. 全局任务状态条出现。
5. Job 完成后，现有轮询逻辑失效分镜查询。
6. 统一页面显示新分镜和可用的关键帧生成按钮。

### 9.2 关键帧生成

1. 单个操作调用现有单分镜关键帧接口；批量操作调用现有批量接口。
2. 后端选择专业图片提示词或分镜画面描述降级。
3. 返回 Job 或批量 Job 后刷新 Job 查询。
4. 任务完成后失效关键帧和分镜相关查询。
5. 卡片显示新的当前关键帧。

### 9.3 视频生成

1. 前端确认该分镜存在已完成的当前关键帧。
2. 单个操作调用现有视频生成接口；批量操作调用现有批量接口。
3. 后端选择专业视频提示词或结构化动作降级。
4. 批量预检继续允许部分成功，并返回跳过原因。
5. 任务完成后失效视频和分镜相关查询。

## 10. 异常与边界处理

- 没有活动项目：沿用 `ProjectRequired`。
- 提取失败：顶部任务状态结束，任务中心显示失败原因，页面保留原有分镜。
- 批量部分失败：Toast 显示成功数量、跳过数量和逐项原因。
- 缺少图片描述：关键帧单项拒绝入队；批量任务跳过该分镜。
- 缺少当前关键帧：视频单项按钮禁用；批量任务跳过该分镜。
- Provider 未配置或不可用：沿用现有后端错误和任务失败处理。
- 项目切换：清空当前选择，任务状态条只显示新项目的 Job。
- 任务完成、失败或取消：轮询不得继续把任务视为活动状态。
- 旧路由访问：跳转到统一页面并定位对应区域。
- 大量分镜：关键帧和视频列表继续通过 React Query 按分镜缓存并共享请求；当前版本立即展示，历史版本沿用横向滚动列表。

## 11. 组件与文件边界

预计前端边界：

- `components/task-loading-bar.tsx`：纯展示和任务汇总，不负责请求。
- `lib/job-labels.ts`：公共任务类型名称。
- `hooks/use-job-polling.ts`：继续负责轮询和任务完成后的查询失效。
- `components/app-shell.tsx`：导航和全局任务状态条挂载。
- `pages/ShotsPage.tsx`：统一页面编排、来源、范围、选择、批量操作和现有分镜卡片。
- `components/shot-media-card.tsx`：作为可复用媒体阶段嵌入分镜卡片，保留现有媒体能力。
- `App.tsx`：统一标准路由和旧路由兼容。

预计后端边界：

- `services/prompt_service.py`：新增关键帧和视频的确定性有效提示词函数。
- `services/media_service.py`：在关键帧和视频入队时调用上述函数，并在无可用描述时拒绝入队。

不改 Job 数据模型、媒体数据模型和现有 API 路径。

## 12. 测试设计

### 12.1 前端单元测试

- 单任务活动时顶部状态条显示任务名称和状态。
- 多任务活动时显示正确活动数量。
- 没有活动任务时隐藏。
- 批量任务按终态数量计算进度，存在失败时不显示全部成功。
- 点击任务状态条进入任务中心。
- 项目切换后清空分镜选择。
- 批量关键帧和视频继续展示部分成功、跳过项及原因。
- 旧 `/keyframes`、`/videos` 地址跳转到统一页面。
- 单个分镜卡片同时提供关键帧和视频生成入口。

### 12.2 后端 pytest

- 有 `image_prompt` 时关键帧优先使用专业提示词。
- 缺少 `image_prompt` 时使用 `frame_description`。
- 两者都为空时返回具体错误。
- 有 `video_prompt` 时视频优先使用专业提示词。
- 缺少 `video_prompt` 时使用结构化动作降级。
- 无有效动作内容时返回具体错误。
- 批量生成对不可生成项保持部分成功语义。

### 12.3 Playwright

- 创建项目并从小说提取分镜。
- 不离开统一页面生成单个关键帧。
- 在同一页面生成单个视频。
- 批量关键帧和批量视频入口可用。
- 当前关键帧和当前视频可见。
- 旧路由可兼容跳转。
- 桌面和 390px 窄屏导航只显示一个“分镜视频”生产入口。
- 后台任务执行时页面顶部存在任务状态条，切换业务页面后仍存在。

## 13. 验收标准

- 生产导航中只保留一个“分镜视频”入口。
- 从小说或当前剧本提取后，无需离开页面即可发起关键帧生成。
- 支持单个、选中项、指定场次和全部关键帧生成。
- 支持单个、选中项、指定场次和全部视频生成。
- 分镜、提示词、关键帧和视频的现有编辑与版本能力全部保留。
- 任意持久化后台 Job 启动后，当前页面顶部显示持续 Loading。
- 切换业务页面时活动任务状态不消失。
- 任务完成、失败、取消或中断后状态条不会卡住。
- 批量任务部分失败时反馈准确，不回滚已完成结果。
- `/keyframes` 和 `/videos` 旧地址仍能进入统一页面。
- 不创建数据库迁移，不改变现有 API 路径。
- 前端单元测试、后端目标 pytest、前端构建和相关 Playwright 场景通过。
