# 平台项目存储根目录设置设计

## 目标

用户在平台内通过 Windows 原生文件夹选择框设置一次项目存储根目录。后续新建项目时，平台在该根目录下按项目名创建独立目录，并在项目目录内创建分类素材目录。

示例：

```text
D:/漫画项目/
├── 项目1/
│   ├── 角色/
│   ├── 物品/
│   ├── 场景/
│   ├── 分镜关键帧/
│   └── 分镜视频/
├── 项目1 (2)/
└── 项目1 (3)/
```

结构化信息继续保存在 SQLite 数据库中；图片、视频等媒体文件保存在上述分类目录中。

## 用户流程

1. 用户进入侧边栏“平台设置”页面。
2. 用户点击“选择目录”，后端在本机弹出 Windows 原生文件夹选择框。
3. 用户确认目录后，平台验证目录安全性和可写性并立即保存，无需重启。
4. 用户新建项目时，平台读取当前根目录，创建项目目录和五个分类目录。

用户取消目录选择时保持原设置不变。更换根目录只影响之后新建的项目，已有项目不搬迁、不改路径。

## 目录命名

- 项目目录使用经过 Windows 文件名清洗后的项目名。
- 若目录已存在，依次尝试 `项目名 (2)`、`项目名 (3)`，绝不复用或覆盖已有目录。
- 使用原子 `mkdir(exist_ok=False)` 处理并发创建冲突。
- 项目改名不重命名存储目录，避免已有媒体路径失效。
- 项目名和完整路径继续受 Windows UTF-16 及路径深度限制保护。

## 数据模型

新增 `platform_setting` 表：

- `key`：设置键，主键。
- `value`：设置值。
- `updated_at`：更新时间。

项目存储根目录使用键 `project_storage_root`。数据库没有该设置时，回退到 `APP_PROJECTS_DIR`，再回退到 `workspace/projects`。

项目表新增：

- `storage_root`：项目创建时使用的绝对根目录。
- `storage_layout`：目录布局版本；旧项目为 `prefixed`，新项目为 `categorized`。

保留现有 `storage_name`：

- 旧布局中表示分类目录前缀。
- 新布局中表示实际项目目录名，包括可能追加的 ` (2)` 序号。

项目实际目录计算规则：

- `prefixed`：`storage_root / project_id`。
- `categorized`：`storage_root / storage_name`。

迁移时，已有项目写入当前有效的项目根目录并标记为 `prefixed`，因此原媒体路径保持可用。

## 后端接口

新增平台设置接口：

- `GET /api/settings/project-storage`：返回当前有效根目录及其来源。
- `POST /api/settings/project-storage/select`：弹出原生目录选择框；选择成功后验证并保存，取消时返回未选择状态。

目录选择通过可注入的选择器服务实现，生产环境使用 Windows 原生对话框，测试使用替身，不启动真实窗口。

根目录保存前验证：

- 必须是绝对目录且不能是磁盘根目录。
- 不能指向平台源码、工作区本身或其上级目录。
- Windows 路径不能过深。
- 必须可创建目录和临时文件；验证产生的临时文件立即清理。

## 文件服务

文件服务根据每个项目持久化的 `storage_root`、`storage_name` 和 `storage_layout` 解析实际目录，不再假定所有项目共享当前全局根目录。

新布局的媒体路径：

- 角色：`角色/<asset_id>/vNNN.<ext>`
- 物品：`物品/<asset_id>/vNNN.<ext>`
- 场景：`场景/<asset_id>/vNNN.<ext>`
- 关键帧：`分镜关键帧/<shot_id>/vNNN.<ext>`
- 视频：`分镜视频/<shot_id>/vNNN.<ext>`

旧布局继续按原有相对路径和带项目名前缀的分类目录读取。

## 媒体访问

`/media/{project_id}/{relative_path}` 根据数据库中的项目记录动态解析项目实际目录，不再依赖单一静态根目录挂载。

每次访问必须：

- 确认项目 ID 存在。
- 拒绝绝对路径和 `..` 路径穿越。
- 确认解析后的文件仍位于该项目实际目录内。
- 仅返回真实文件；不存在时返回 404。

这样更换全局根目录后，新旧项目可以同时访问，也不会暴露用户选择目录中的其他文件。

## 前端

侧边栏新增“平台设置”入口，页面包含：

- 只读的当前项目存储根目录。
- 带文件夹图标的“选择目录”按钮。
- 选择中、取消、成功和失败反馈。
- “仅影响之后新建项目，已有项目不会自动搬迁”的说明。

项目页面继续显示当前项目的实际绝对存储路径。

## 错误与清理

- 用户取消选择：不报错、不修改设置。
- 目录不可写或不安全：返回可执行的中文错误信息，保留旧设置。
- 项目目录创建失败：不插入项目记录，并清理本次已创建的空目录。
- 数据库写入失败：只清理本次创建的项目目录，不碰已有同名目录。
- 删除项目：只删除该项目记录中解析出的直接子目录，校验失败时拒绝删除。

## 测试

后端覆盖：

- 设置读取、默认回退、保存和取消。
- 不安全、不可写、过深目录拒绝。
- 同名项目依次创建 `项目名`、`项目名 (2)`、`项目名 (3)`。
- 新项目自动创建五个分类目录。
- 新旧布局的角色、物品、场景、关键帧和视频写入路径。
- 根目录切换后旧项目仍可读取，新项目写入新根目录。
- 动态媒体路由的正常读取、中文及特殊字符、404 和路径穿越保护。
- 创建失败和删除操作不污染已有目录。

前端覆盖：

- 平台设置页面显示当前根目录。
- 选择成功后更新显示并反馈成功。
- 取消选择不修改当前值。
- 接口失败时显示错误。
- 项目页面继续显示项目实际存储路径。

## 不包含

- 不自动搬迁已有项目。
- 不允许浏览器直接提交任意绝对路径。
- 不把项目文本、提示词或状态复制为文件。
- 不创建 commit 或 push。
